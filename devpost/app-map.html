Merge Desk, mapped

A snapshot of main at commit 8960272 (2026-10-23). Code drifts; search the anchors below if a path moves.

What it is, in three pieces

Gemini proposes

Reads both sides of a conflicted pull request, says what each side meant, offers options, then writes the merge for the option you pick.

Code decides

A fresh Vercel Sandbox with the network off checks the merge: it parses, the chosen option was honored line by line, and the real tests pass. Anything else is HELD.

Land is guarded

Only a VERIFIED run can Land: a merge commit on the pull request's own branch after rechecking the exact head and base. Never main, never a force push.

One action: pressing Run checks

  1. Desk: Run checks (src/ui/Run.tsx)
  2. POST /api/live/run (src/app/api/live/run/route.ts)
  3. runPipeline: propose (Gemini), write and parse, honor (plain code), tests (Vercel Sandbox)
  4. Result event: HELD or VERIFIED, back on the desk

A reference route through the code

Three stops that explain most of the product. This is a reference route, not a record of a guided tour.

  1. The button and the result card

    src/ui/Run.tsx, search export function RunSection and Every check passed on a scratch copy. The button sends the option the slider is on; the card shows the verdict, the failed step and the MISSING or present lines.

  2. The pipeline, in order

    src/server/pipeline/run.ts, search export async function* runPipeline. Each step is yielded as an event the desk draws live. The verdict is VERIFIED only when every step passed: ORDER.every.

  3. The check the model can't talk past

    src/core/honor.ts, search export function checkChoiceHonored. For the chosen option, every line each side changed must be in the merge (or dropped as chosen), and nothing outside the conflicts may change.

And after VERIFIED: Land

src/server/guard.ts checkLand refuses anything not VERIFIED, a closed or forked pull request, the default or base branch, or a head or base that moved. src/server/github/land.ts landMerge then writes the merge commit with parents head and base and moves the branch only from the expected head.

A practice to reuse

Rehearse the exact demo path on real, messy data before you record it. The seeded demo pull requests never move, so they hide whole classes of bugs. Twice, running Merge Desk on its own repository found one the unit tests didn't:

  • 2026-10-07: GitHub's base.sha is the base from when the pull request opened, so a moved main was invisible. Evidence: docs/evidence/dogfood-2026-10-07.md, fixed in PR #11.
  • 2026-10-23: pull request #10, now 129 files behind main, produced a patch over the result event's limit, so the desk would have rejected the verdict mid-recording. Evidence: PLAN.md row 2.13, fixed on branch fix/large-run-result with a test that fails without it.

On another project: before a demo or a release, run the real pipeline once on the oldest, largest real input you have, not the fixture, and read every event it emits.
