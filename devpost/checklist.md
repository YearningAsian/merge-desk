# Build Checklist

Build mode: fast (chosen 2026-10-05)

Learner conditions for fast mode (2026-10-05):
- Stop only at the hands-on checks below (after slice 3, after slice 5, final review), after slice 2 to report sandbox timings before any screen is built, whenever a slice fails verification twice, and before any spec change.

## Revisions

- The clean scenario merges the retry into `demo/base` first and leaves the rename open as the pull request: the scope's held line is "theirs: retry on 429, MISSING", so the retry has to be the base side.
- The drop scenario uses a third playground file (`src/money.js`), and the held scenario's stale caller lives in a new file (`src/fees.js`): separate files keep the scenarios from interfering, and a caller outside the conflicted file is exactly what only the real tests can catch.
- Scripts are TypeScript ES modules run with `tsx` (`scripts/*.mts`) instead of `.mjs`: they reuse the tested scope guard and schemas in `src/core`, and tsx compiles plain `.ts` as CommonJS in this package.
- The `main` protection is two rulesets, applied in slice 1 (learner condition): a ruleset's bypass list applies to all of its rules, so "no force push or deletion" (everyone) and "only admins update" (admin bypass) had to be separate.
- The choice-honored check merges lines both sides changed at the token level, beyond the spec's rename rule: renames are one case of it, and a line that can't be merged that way fails closed as ambiguous.
- The run pipeline takes the conflicted paths up front (from the analysis, or the scenario config for `npm run gate`) and still runs the tests after a failed choice-honored check: a proposal touching any other file is refused before anything is written, and a hold shows both pieces of evidence.
- Both runners share one working-copy module (`src/server/runner/workspace.ts`: merge, conflict reading, write and commit, parse, tests); `LocalRunner` and `SandboxRunner` only supply the shell, so a merge is held or verified by the same code wherever it runs.
- The TypeScript parse check runs on the server with the app's pinned TypeScript 6 (syntax only, it never executes the candidate) for both runners, instead of inside the dependency snapshot. Same compiler and lockfile; slice 8 can still move it.
- The analysis carries the conflicted files' three versions and git's conflict text, signed with it, so the run's proposal is written from exactly what was analyzed without asking GitHub again.
- Gemini: `thinking_level: "low"` (`minimal` is refused by `gemini-3.8-flash`). The SDK may retry a 429 or 5xx up to twice inside the same 30-second deadline; that transport retry is separate from the pipeline's at most two retries on a malformed answer or a failed parse. Found on 2026-10-05, when Gemini answered 503 "high demand" for most calls.
- The sandbox reads each command's raw exit code: the SDK reports a missing exit code as 0 on its fast path, so a killed command could otherwise look like a pass. A missing code now means "no exit code" (held).
- Sandbox facts from the live runs (2026-10-05): the `node:24` image clones the git source into `<cwd>/<repository name>` (`/vercel/merge-desk`), runs as the non-root `ubuntu` user with Node v24.19.0 and git 2.53.0. A whole held round (create, fetch, deny-all, merge and write, parse, tests, stop) took 6.0 to 9.7 s, the tests 0.6 to 1.2 s, and reading both sides about 4.5 s. Well inside the 30-second and 2-minute targets, so no fallback is needed.
- Gemini model: `gemini-3.8-flash` (the spec's default) answered 503 "high demand" to every analysis-sized request on 2026-10-05 on the learner's free-tier key; its structured output was confirmed on a tiny call. Slice 2 was verified with the existing `GEMINI_MODEL` override set to `gemini-3.5-flash-lite`: valid answers in about 1.4 to 2 s, held and verified exactly as planned. `gemini-3.5-flash` answered validly but in 38 s (over the deadline); `gemini-2.5-flash` is retired. The code default is unchanged until the learner decides.
- Learner decision (2026-10-05): the default model is `gemini-3.5-flash-lite`, the most cost-effective model that worked. Both Flash-Lite models are free on the free plan; `gemini-3.1-flash-lite` is cheaper on the paid plan but timed out on 2 of 4 held-scenario calls and recommended combining the two competing rounding fixes. Spec, stack doc, ADR 0001 and `.env.example` updated.
- Slice 3 (2026-10-05): the shadcn sources were copied with `shadcn view` (CLI 4.21.2, a patch over the planned 4.21.1) into `src/ui/primitives` and restyled, instead of `shadcn init`, which would have rewritten the BRAND tokens. `components.json` records the aliases.
- The pull request list uses rows that are buttons with one tab stop (J/K and Up/Down move focus, Enter or Space opens) instead of an ARIA listbox: the "Can merge" toggle can't live inside a listbox, and buttons give Enter/Space for free. Focus (outline) and the open row (filled, with an ink bar) stay distinct. List words are Needs resolution, Analyzing, Options ready, Analysis failed, Checking and Can merge; red and green stay reserved for HELD and VERIFIED.
- Diffs use Shiki's `github-light-high-contrast` theme on GitHub's own line washes: Pierre's default `github-light` tokens on its washes failed axe's 4.5:1 contrast check.
