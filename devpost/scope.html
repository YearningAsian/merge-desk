Merge Desk

scope: approved

A merge you can watch and understand. An AI proposes the resolution, you see what each side meant and what the merge did, and checks run live in front of you before anything lands. On your phone or your computer.

The kernel

Merge conflicts stop being a black box. Each side is shown as a plain-language intent next to a visual diff, the proposed merge is checked live for both intents and the tests, and a merge that drops a teammate's change is held with the missing intent named.

Ours intendsrename fetchUser to getUser
Theirs intendsretry fetchUser on HTTP 429

Who it's for

A developer on a small team whose pull request just went red with a conflict because a teammate merged first. Today: raw conflict markers, guessing what the teammate meant, push, wait for CI, test by hand, repeat.

"I love working with teammates but hate dealing with merge conflicts and spending lots of time trying to fix it."

First user: the learner, on this very repository.

What "working" looks like

On a phone, open Merge Desk on the merge-desk repo itself, where two real branches from this build conflict.

  1. Open the conflicting pull request

    Both sides appear as one-line intents above a side-by-side diff.

  2. HELDThe merge that drops a side

    Fails live: "theirs: retry on 429, MISSING". Nothing is pushed.

  3. VERIFIEDThe merge that keeps both

    Checks tick green as you watch: parses, both intents kept, tests pass. Tap Land; GitHub shows the pull request can merge.

Boundary

Now: the proof of concept 6
  • Connect one GitHub repository (merge-desk for the demo).
  • List its pull requests that GitHub reports as conflicting.
  • Conflict view: plain-language intents, side-by-side diff, Gemini-proposed merge, one line on what the merge did.
  • Live checks streamed on screen: parses, both intents present, tests pass.
  • Land: commit the checked resolution to the pull request's own branch. Held merges push nothing.
  • One responsive web app for phone and desktop.
Later 7
  • Full dashboard of projects, pull requests and merges ("an easy to navigate GitHub").
  • Installable desktop / home-screen app that stays out of the way.
  • Expo React Native app with a downloadable Android APK, once the web app works end to end.
  • Many repositories, sign-in with GitHub, notifications.
  • A git merge driver so git merge uses the same checks.
  • More AI providers, with fallback.
  • Replay test over real historical merges.
Cut, with reasons 3
  • App-store releases: review time, nothing for the kernel; the APK covers native.
  • Rebuilding GitHub in general: not the kernel; the dashboard waits for Later.
  • Merging into main for you: Merge Desk makes the pull request mergeable; the team merges it.

Why it matters to the learner

"I want to use this myself since resolving merge conflicts are a headache and I wanna make a tool that makes collaboration among devs easier."
