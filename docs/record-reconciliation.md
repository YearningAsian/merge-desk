# Reconcile a local decision-record lock

This procedure is for the operator of the local development server. Hosted decision writes remain refused until shared coordination is configured.

A record write that was dispatched to GitHub but not confirmed keeps its local lock. That prevents a late comment update from overwriting a later decision. The refusal includes an opaque reference such as `merge-desk-record-locks/<64 hexadecimal characters>`. It contains no absolute path or credential. There is no expiry, automatic takeover or automatic unlock.

1. **Pause writes for the affected pull request.** Stop Land, hold and discard requests in every tab and every local server process sharing this temporary directory. Preserve the refusal, pull request, run, comment and branch evidence. A request timeout, browser abort, process exit or server restart does not prove that a dispatched GitHub operation has finished.
2. **Locate the exact lock on the writer's machine.** The directory is beneath the operating system temporary directory returned by Node's `os.tmpdir()`, in `merge-desk-record-locks`. Match the full hexadecimal identifier from the refusal. Use the same machine and operating system account as the writer; keep its absolute local path out of screenshots, public reports and UI copy. A missing or inaccessible directory is a filesystem problem to investigate, not permission to retry.
3. **Reconcile GitHub's current state.** Use an authorized GitHub session to inspect the pull request's comments and current head/base branches. Confirm the relevant comment was authored by this GitHub App; a pasted Merge Desk marker alone is insufficient. Read the record through Merge Desk's authenticated record endpoint so its App identity, seal and pull-request scope are checked. Preserve any invalid, outside-edited or duplicate comments and their evidence. For an ambiguous Land, inspect the branch commits and parents as well; a failed record update does not undo a confirmed branch update.
4. **Resolve the outstanding remote ambiguity.** Establish whether every dispatched comment or branch operation completed, was rejected, or can still apply. A snapshot showing no new comment or commit is not enough: the earlier operation may still be pending. Do not infer completion from elapsed time, an abort, a dead process or a single successful read. If provider responses, current state and preserved evidence do not establish a settled outcome, keep the lock and seek provider or maintainer assistance. Do not retry an ambiguous writer.
5. **Unlock only after reconciliation is complete.** A human operator may remove only the exact matched empty lock directory, after recording the evidence and confirming no writer or unresolved remote operation remains for that scope. Never remove the parent directory, use a recursive deletion, clear every lock, or delete/edit GitHub comments to make the refusal disappear. If the directory is not empty, stop and investigate. There is deliberately no unlock script.
6. **Read before deciding on new work.** Re-read the authenticated decision record and current GitHub branches. Keep an already completed Land as historical evidence. Start only a new, explicitly chosen action when the reconciled state permits it; unlocking does not retry or confirm the earlier operation.

The lock reference identifies coordination state, not a GitHub receipt or a successful decision. If reconciliation cannot establish what happened, the result remains unconfirmed and the lock stays in place.
